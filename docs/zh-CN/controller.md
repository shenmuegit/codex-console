# 独立远控控制端

目标链路是 Web → 本 server → 官方中继 → 被控 Codex 主机。server 拥有自己的
控制端身份，接收每台被控主机提供的码，不要求 server 运行 Codex 桌面应用。
官方连接码流程使用中继，码中没有自定义 server 地址。参见
[远程连接说明](https://learn.chatgpt.com/docs/remote-connections)。

## server 发起浏览器授权

`web/remote-auth.mjs` 用 Node crypto/http 实现已观察到的控制端注册授权码
流程，不加载桌面应用代码、不启动 GUI、不写凭据文件。官方授权链接绑定所
选 ChatGPT 工作区，PKCE verifier 始终留在 server。

内部接口：

```js
const attempt = await startRemoteAuthorization({ accountId });
// 向已认证的所有者显示 attempt.url。
// 浏览器在另一台电脑时，把复制的 localhost 回调 URL 作为数据提交：
attempt.submitCallback(callbackUrl);
const stepUpToken = await attempt.completion;
```

所有者的一次性账号确认仍是官方控制端注册的前提。浏览器在 server 上时，
可直接返回本机回环回调；浏览器在另一台电脑时，server 可以校验复制的回调
URL，不访问该 URL，也无需 SSH 隧道。Web 设置入口和控制端注册是后续独立
实现步骤，不能仅凭这个授权模块宣称它们已经完成。

监听仅绑定 IPv4 回环地址，依次使用官方回调端口 1455、1457。拒绝错误 state、
重复 state/code、缺少 code、复制回调的错误 origin/path 和重复消费。令牌交换
拒绝跳转，请求限时 20 秒；成功、取消、拒绝或超时后均关闭回调监听。授权等待
最多十分钟，返回凭据只交给 server 调用方。

在 `web/` 中执行 `node --test test/remote-auth.test.mjs` 和 `npm test` 验证。
检查使用真实本机回调监听及受控令牌接口，证明 server 流程的保护措施，不等于
OpenAI 实际注册成功。原生公开 OAuth client 和注册 scope 来自已安装版本
26.928.21956，独立控制端的官方兼容性仍待验证。

## 受保护密钥注册与主机连接码

`web/remote-controller.mjs` 已实现注册、刷新、提交连接码和主机列表。传入
仓库外的私人 `authFile`、权限 700 的外部 `stateDir`，以及设备密钥组件的
create/get/sign/delete 方法。模块保留日常认证文件，不复用其他设备的控制端
ID；注册前校验账号、挑战的用途/audience/目标/有效期、密钥身份、最新授权
scope，以及自身生成的签名。

与观察到的官方客户端一致，step-up 令牌必须匹配日常账号令牌中的当前工作区
用户。登记服务可能返回同一账号的登录用户身份；该身份继续绑定挑战、设备证明
和登记记录，不能替代授权时的工作区用户。仍拒绝缺少工作区身份、错误账号或
scope，以及过期的重新认证。

先完成网页确认，再由服务器申请短期登记挑战并创建受保护密钥。所有者确认
期间，私人进程归属记录占用设置流程，尚无远端 client 或密钥。随后仍使用
已有的官方 start/finish 接口，并在签名前校验新挑战，避免两分钟挑战在
最长十分钟的网页确认期间过期；不延长或跳过服务方的挑战有效期。

server 身份和中继会话一起写入私人 `enrollment.json`，以 600 权限原子发布，
初次注册不覆盖已有记录。`pending.json` 仅标识 server 自己的待注册身份及
所属进程。重复点击设置或另一进程正在授权时，拒绝重复注册。失败时分别清理
本次身份的密钥和远端记录，清理失败则保留私人重试记录。账号变化或密钥缺失、
不匹配时保留已有记录，并阻止提交连接码；中继会话过期后使用原密钥刷新。

已把原生密钥组件复制到私人且忽略提交的
`.tools/controller-key/remote-control-device-key.node`，校验其 SHA-256 为
`517ddc383936597370f731df1d64ba6bf97555756c1b770900db608911dad8ff`。
从这个独立路径执行临时密钥的创建、读取、签名、独立验证和删除均通过，
不加载应用 JavaScript，也不启动桌面进程。组件要求 Linux TPM 资源管理设备
可用。当前 server 使用加密的软件 vTPM；组件报告 `hardware_tpm`，但不能
据此宣称存在物理硬件保护，重启后自动启动仍待配置。

在 `web/` 执行 `node --test test/remote-controller.test.mjs` 和 `npm test`。
当前验证覆盖 13 个控制端场景及 342 项 Web 测试。注册夹具使用独立 ECDSA
签名校验，不能证明官方服务实际接受注册。所有者授权、实际注册/配对、中继
RPC 控制和 Web 设置入口仍待完成及验证。

## 中继传输与主机隔离

`web/remote-relay.mjs` 实现已观察到的 v3 中继协议。Node 24 内置 WebSocket
可发送所需认证头；真实本机握手和 CONNECT 代理检查均通过，无需新增依赖。
本机使用已配置的代理时，以 `--use-env-proxy` 启动服务。参见底层
[Undici WebSocket 接口](https://github.com/nodejs/undici/blob/main/docs/docs/api/WebSocket.md)，
其 Node 初始化选项支持额外请求头。

控制端仅供 server 调用的 `session()` 现在提供私人握手请求头及
`signChallenge()`。签名前校验 client/账号身份、会话令牌摘要、目标、有效期、
nonce 和 scope。这个对象不能序列化给浏览器，公开设置状态使用 `status()`。

每台主机使用独立 UUID、序号及原生客户端。即使两台主机使用
相同 RPC 或审批 ID，回复、通知和审批答案仍留在对应主机。单帧限制 153,600
字节，消息限制 32 MiB，全部未完成消息的存储限制 64 MiB。UTF-8 按字节分片，
拼接完成后才解析 JSON；丢弃重复消息，序号缺口使对应主机重新连接。

断线使未完成调用以结果未知的状态失败。新连接初始化新的主机数据流，恢复
原生快照，不静默重发执行请求。ping 保持数据流存活，心跳检查账号和密钥、
刷新会话；会话租期结束后重新连接。

传输检查使用真实本机 WebSocket 对端，独立验证设备签名，覆盖两台主机、ID
冲突、审批路由、错误挑战/身份、重复消息、分片、序号缺口及不重发执行请求的
重连。它们仍不能证明与真实官方主机互通。Web 设置/主机路由和所有者实际授权
是后续集成验证关卡。

## Web 设置与设备路由

侧栏“系统设置 → 连接设备”打开现有 owner 认证的设备弹窗、官方授权链接、复制回调
输入、被控主机连接码输入和设备选择。设置及接码要求已有 owner 登录及正确
页面来源；只返回授权 URL、有效期和公开状态，控制端凭据及签名接口留在
server。

设备名称暂存在当前浏览器标签页中，切换机器后，即使清单尚在读取或暂时
失败，也保留已知名称。只缓存 ID 和显示名称，连接状态及授权仍以实时结果
为准。未知设备使用可读提示，登录失效或控制端取消授权时清除这些提示。

“系统设置”也包含“7 天用量”。关闭按钮或 Escape 关闭子弹窗后，返回设置
并将焦点放回所用入口；关闭设置则回到侧栏。用量斜杠命令继续沿用原有入口。

在仓库外的私人配置中启用：

```json
"remoteController": {
  "deviceKeyModule": "/absolute/private/remote-control-device-key.node",
  "stateDir": "/absolute/external/controller-state"
}
```

密钥组件必须属于服务用户，禁止组或其他用户访问；控制端状态在仓库外。
受管理且启用控制端的单元用 `--use-env-proxy` 启动 Node；未启用的本机配置
仍可使用。

server 通过连接池连接已配对主机，每台主机有独立的原生客户端、视图、事件流
及私人状态目录。各 Web 处理器共享 owner 登录，在路由前验证身份。未知主机
不回退到本机后端；账号变化后关闭已有远端客户端。本机 API 保持可用，当前
完整测试 374 项通过。

远端文件系统与浏览器设备作用域已实现，下文说明测试夹具覆盖范围。Web 入口
不能证明官方服务已接受注册或配对，仍必须完成所有者授权和真实官方主机测试。

启动先通过不带设备参数的状态请求确认 owner 登录，再初始化所选设备。未知或
已移除主机、控制端未登记或账号不可用、原生启动失败均在工作区仅显示简洁的
错误原因和错误码，不在错误区域添加设备选择器或恢复按钮。侧栏设备选择保留
当前主机身份及暂不可用占位项，设备管理位于“系统设置 → 连接设备”。已知
上游连接失败以 HTTP 502 返回原有原因，未知内部异常仍隐藏其细节。
只有实际 HTTP 401 才显示 owner 密码登录。
失败的远端请求不会回退本机；切换设备会关闭旧视图/事件流，不带入旧设备的模型
或事件游标。

## 远端路径、附件与浏览器草稿

所选设备的原生初始化提供 `platformFamily` 和 `codexHome`。Unix 与 Windows
路径按该设备的规则处理（包括盘符和 UNC 路径），不会在服务器文件系统中解析
或打开远端路径。远端项目创建、会话创建、文件补全和输入框引用使用原生文件
系统 RPC。新建远端会话需要选择原生项目，服务器配置的本地目录不是远端默认目录。

检查到的原生源码中，`fs/watch` 只回传输入路径，尽管协议注释称其返回规范路径。
因此逐级调用 `fs/getMetadata` 检查所有祖先目录，拒绝缺失路径和符号链接。
下载在读取前后重新检查作用域和原生时间戳。原生 RPC 没有 inode 或原子的
no-follow 文件句柄，不能提供与本地下载相同的原子替换保护。远端读取使用整份
Base64 RPC 结果，不是远端文件描述符流；大文件可能超过当前 relay 实现的
32 MiB 消息上限，失败不会回退读取服务器文件。

上传保留原有的有界服务器暂存、文件名和照片格式校验、本地 no-follow 检查，
每个设备使用独立的私有状态目录。发送附件时，通过原生 `fs/writeFile` 将原始
字节写入 `<远端 codexHome>/console-uploads/<不透明上传 ID>/content[.扩展名]`，
并把远端路径传给原生输入框。在首次每附件目录/文件变更前持久化传输意图。
RPC 中断或结果未知后，重试核对
已登记的目录和原始字节：写入完成但响应丢失时复用文件，缺失内容才写入，
拒绝变化或未知内容。为让 Base64 和 JSON 容纳在当前 relay 上限内，远端单文件上限为 24,000,000 字节
（配置更低时使用配置值）；本地上限不变。完成的暂存和远端副本保留供会话复用，
尚未自动删除远端副本。

原生 `fs/createDirectory` / `fs/writeFile` 的默认权限不足以保证私有存储。
发送附件字节之前，服务端通过固定的
[`command/exec`](https://learn.chatgpt.com/docs/app-server) 准备并核验目录，继承
主机当前沙箱/权限配置，不覆盖策略、不扩大 writable roots、不修改环境，也不
回退到 `process/*`。浏览器不能提交命令或脚本。每次写入前还必须核验目标
附件目录权限，包括重连后恢复的已登记空目录。只有预写核验允许目标文件尚未
创建；写后核验仍要求文件存在并检查其安全性。

Unix 主机需要**已安装 Python 3**；不能假定每台 Mac 都有，服务端不会安装它。
标准库使用带 `O_NOFOLLOW` 的目录句柄逐级检查所有者和写权限，从创建时就让
`console-uploads` 具备 0700 权限。已有目录必须属于原生执行用户且禁止组和
其他用户访问；附件必须是该用户拥有且仅有一个硬链接的常规文件。准备目录的
响应丢失后可安全重复核验。运行时缺失、沙箱拒绝、已有目录不安全或权限变化
均返回 `REMOTE_STORAGE_NOT_PRIVATE`，浏览器草稿和服务端暂存保留。

Windows 主机需要**系统 Windows PowerShell** 和支持 ACL 的文件系统。固定
编码命令把路径作为 JSON 数据传入，拒绝 reparse point 和不可信/可写祖先，
通过 [`DirectoryInfo.Create(DirectorySecurity)`](https://learn.microsoft.com/en-us/dotnet/api/system.io.directoryinfo.create?view=netframework-4.8.1)
在创建时应用只允许当前用户、禁止继承外部权限的可继承 DACL。核验根目录、
每附件目录和已有文件 ACL，拒绝其他主体的 Allow 条目。不会自动重写已有
不安全权限。运行时/API 缺失、ACL 不可读或主机策略阻止核验时拒绝传输。
Windows ACL 尚未在真实用户设备上验证，夹具检查不能替代实机证据。

上传请求、文件下载、照片预览、Markdown 会话链接、子代理链接、导出与侧边聊天
均保留 `host`。草稿、附件 ID 和待确认恢复信息使用按设备区分的浏览器存储键，
会话 ID 相同也不会混用；已有本地草稿键继续可读。其他设备上的未知 ID 被拒绝，
远端路径不能授权读取服务器本地文件。

在 `web/` 中运行 `node --test test/remote-filesystem.test.mjs test/remote-upload-storage.test.mjs test/host-scope-browser.test.mjs test/codex.test.mjs`
和 `npm test`。Unix/Windows 文件系统与浏览器检查使用测试夹具，不代表真实官方客户端配对成功。
真实设备的读写、事件、双设备并发和重连仍是需要用户授权完成的验证门槛。

中继数据流不另存 RPC 待处理队列；原生调用超时会释放唯一的待处理调用表。
不带请求 ID 的中继错误只关闭对应主机的数据流，未完成调用以结果未知失败，
不会猜测已过期的请求 ID，也不会重放执行请求。

服务返回候选 client ID 后，在挑战校验或建钥之前立即记录本操作及进程所有权；
授权前补充密钥身份。清理失败保留私人重试记录，重启后可定向清理，不覆盖
另一操作的记录。`CLEANUP_RECORD_FAILED` 明确表示存储失败、需要管理员恢复；
本次候选身份尚未处理完时不要另行注册。

HTTP 请求和中继握手前检查基础账号令牌的有限 `exp` 并续期。生产续期通过
server 已有的回环原生后台凭据管理器，以固定内部 `getAuthStatus` 调用传入
`includeToken: false`、`refreshToken: true`；不运行桌面 JavaScript，也不直接
修改 `auth.json`。并发续期共享同一次操作。完成后重读私人缓存，核验账号、
工作区及主体，再继续使用原控制端身份和密钥。浏览器不能调用这个旧版原生
方法，也拿不到它的令牌。

过期或被拒绝的凭据公开显示 `authenticationRequired`，原生续期失败显示
`authenticationUnavailable`；`enrollmentPreserved` 标记使 Web 禁止重复注册。
普通官方 server 账号登录若确实撤销，先恢复该登录，再刷新设备弹窗。401
使原请求以结果未知失败；续期不会自动重放配对或其他执行请求，明确重试前
应先核对结果。认证失败及账号变化均保留私人注册记录与受保护密钥。回归
检查使用假凭据；真实用户登录及官方设备互通仍须另行验证。

本地远控身份绑定要求 JWT 工作区声明与私人缓存中所选工作区相符，续期后也
重新核验，才信任远控主体；同工作区的旧版 `user_id` 回退仍可用。这是远控
身份规则，不重新定义普通 Codex 认证或外部令牌的工作区请求头覆盖行为，
普通登录文件保持原样。

当前服务部署及待完成的实机门：[服务验证记录](controller-service-verification.md)。
